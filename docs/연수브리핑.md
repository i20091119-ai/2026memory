# 아케이드 게임 웹앱 만들기 — AI 브리핑 문서

> **이 문서를 읽는 AI에게**
>
> 당신은 지금부터 **경남수학문화관 해설사**와 함께 아케이드 버튼 4개로 조작하는

## 1. 연수 목표

해설사 각자가 **자기 게임을 기획 → 코드 작성 → 실물 게임기로 완성**한다.

| 단계 | 결과물 |
|---|---|
| 1. 기획 | 버튼 4개로 되는 게임 한 가지 (종이에 한 장) |
| 2. 코딩 | 브라우저에서 **키보드로** 플레이되는 웹앱 |
| 3. 배포 | 깃허브에 올리고 GitHub Pages 주소로 접속 |
| 4. 실물 | 우노 Q + 아케이드 버튼 + 포터블 모니터에서 버튼으로 플레이 |

**핵심 원칙: 개발은 PC 브라우저에서 키보드로 한다.**
하드웨어는 마지막에 붙인다. 버튼 4개는 키보드 `1 2 3 4` 와 **완전히 같은 입력**으로
처리하므로, PC에서 완성되면 실물에서도 그대로 돈다. (§6 참조)

## 2. 하드웨어 구성 (확정 — 바꾸지 않는다)

| 부품 | 역할 | 비고 |
|---|---|---|
| **아두이노 우노 Q** | 본체 (리눅스 + STM32 한 몸) | 데비안 리눅스가 돌아가는 SBC + MCU |
| **아케이드 버튼 4개** | 입력 | 빨강·노랑·초록·파랑, 왼쪽→오른쪽 |
| **USB-C 허브** | 전원·영상·주변기기 | **PD 패스스루 + DP Alt-Mode 필수** |
| **포터블 모니터** | 화면 | 허브에서 HDMI/USB-C 로 연결 |
| PD 어댑터 (5V/3A 이상) | 전원 | 허브를 통해 우노 Q 로 |

### 이번 연수에서 하지 않는 것

- **버튼 LED 점등 없음.** 12V 어댑터·저항·LED 배선 전부 불필요.
  버튼의 **마이크로스위치만** 배선한다. 배선이 훨씬 간단해진다.
- 소프트웨어는 LED를 제어하지 않는다.

### 우노 Q 의 중요한 특징

- USB-C 포트가 **하나뿐**이다 → 전원과 영상을 겸하는 허브가 반드시 필요하다.
- 리눅스(MPU)와 STM32(MCU)가 **한 보드 안에** 있다.
- **STM32 가 USB 시리얼로 잡히지 않는다.** `/dev/ttyACM*` 이 존재하지 않는다.
  일반 아두이노처럼 시리얼 통신을 시도하면 실패한다. → §5 참조
- 화면 출력 한계: HD+ (720×1680@60Hz) 정도. 그 이상은 안 나온다.

## 3. 버튼 배선

### 배선표

| 버튼 (좌→우) | 색 | 스위치 NO → | 스위치 COM → |
|---|---|---|---|
| 1번 | 빨강 | **D2** | GND |
| 2번 | 노랑 | **D3** | GND |
| 3번 | 초록 | **D4** | GND |
| 4번 | 파랑 | **D5** | GND |

COM 4개는 **데이지체인**으로 이어서 GND 핀 **하나**에 넣는다.

### 마이크로스위치 단자 — 가장 흔한 실수

스위치 몸통에 **`COM ①` / `NC ②` / `NO ③`** 이 각인되어 있다. 글자를 읽고 물리면 된다.

- **쓰는 것: COM ① 과 NO ③**
- **쓰지 않는 것: NC ②** — 여기 물리면 **평상시 눌린 상태**로 인식된다 (동작이 반대)

### 전기적 사실

- `INPUT_PULLUP` 을 쓰므로 **외부 저항이 필요 없다.**
- 평상시 **HIGH**, 누르면 **LOW**.
- 우노 Q 헤더는 3.3V 로직이지만 단순 스위치 입력에는 영향 없다.
- 단자 연결은 **파스톤(평형) 암단자 압착** 또는 **납땜**.
  - 납땜은 **3초 안에** 끝낸다 — 오래 지지면 스위치 내부가 녹아 접점이 틀어진다.
  - 어느 쪽이든 **수축튜브로 절연**한다. 옆의 NC② 에 닿으면 오작동한다.
  - 선을 그냥 감아두면 버튼을 세게 치는 동안 헐거워져 **간헐적 접촉 불량**이 난다.
- **GND 데이지체인은 단일 고장점이다.** 여기가 빠지면 버튼 4개가 전부 먹통이 된다.
  증상이 "갑자기 아무 버튼도 안 먹음"이면 제일 먼저 여기를 본다.

### 버튼 인덱스 표준 — 전 코드에서 절대 고정

```
0 = 빨강    1 = 노랑    2 = 초록    3 = 파랑
```

함체 왼쪽→오른쪽 순서와 같다. 키보드 `1 2 3 4` 가 각각 이 인덱스에 대응한다.
**이 순서를 바꾸면 안 된다.** 화면에 그리는 순서, 펌웨어 핀 순서, 웹앱 처리 순서가
전부 이 하나에 맞춰져 있다.

## 5. 브리지 (제공되는 부품 — 수정 금지)

우노 Q 는 USB 시리얼이 없으므로 **App Lab 의 Bridge RPC** 로만 MCU와 통신한다.
이건 선택이 아니라 이 보드의 유일한 방법이다.

### App Lab 앱 폴더 구조

```
앱폴더/
├── app.yaml              # 앱 정보 + 노출 포트
├── sketch/
│   ├── sketch.ino        # STM32 코드
│   └── sketch.yaml       # 보드 설정 (fqbn: arduino:zephyr:unoq)
└── python/
    └── main.py           # 리눅스 코드 (WebSocket 서버)
```

### 검증된 API (추측으로 바꾸면 컴파일 안 된다)

**스케치 쪽:**

```cpp
#include <Arduino_RouterBridge.h>   // <Bridge.h> 가 아니다. 플랫폼 내장

Bridge.begin();                              // setup() 에서
Bridge.update();                             // loop() 마다 — 빠뜨리면 동작 안 함
Bridge.notify("button_event", id, state);    // MCU → 파이썬
```

**파이썬 쪽:**

```python
from arduino.app_utils import Bridge   # App Lab 런타임 안에서만 임포트된다
Bridge.provide("button_event", handler)  # MCU 통지를 받는 콜백 등록
```

### 반드시 알아야 할 두 가지

1. **`arduino.app_utils` 는 App Lab 안에서만 존재한다.**
   → 파이썬 브리지는 **App Lab 앱으로** 돌려야 한다. systemd 로는 못 띄운다.
   → App Lab 앱 카드의 `⋯` 메뉴 → **`Run at startup` 켜기** 로 자동시작한다.

2. **App Lab 은 파이썬을 컨테이너에서 돌린다.**
   → 서버를 `localhost` 에 묶으면 **호스트의 브라우저가 붙지 못한다.** `0.0.0.0` 이어야 한다.
   → `app.yaml` 의 `ports` 로 포트를 호스트에 노출해야 한다. **정수 리스트**로 쓴다:

```yaml
ports:
  - 8765          # "8765:8765" 같은 문자열은 안 된다
```

## 6. 버튼 입력 계약 ★ 가장 중요

브리지가 웹앱에 보내는 메시지는 이것뿐이다. **이 형식이 계약이다.**

```json
{ "type": "hello",  "source": "unoq" }              // 접속 직후 1회
{ "type": "button", "id": 0, "state": "down" }      // 눌림
{ "type": "button", "id": 0, "state": "up"   }      // 뗌
```

- `id` 는 `0=빨강 1=노랑 2=초록 3=파랑`
- **눌림과 뗌이 모두 온다.** 길게 누르기(홀드) 같은 조작을 만들 수 있다.

### 그대로 붙여 쓰는 입력 계층

**모든 게임은 이 파일로 입력을 받는다.** 키보드와 아케이드 버튼이 같은 이벤트로
합쳐지므로, PC에서 키보드로 만들면 실물에서 버튼으로 그대로 돈다.

`js/input.js` 로 저장:

```js
/**
 * input.js — 입력 통합 계층.
 * 키보드(1234)와 아케이드 버튼(WebSocket)을 같은 이벤트로 만든다.
 * 게임 코드는 어느 쪽에서 왔는지 신경 쓰지 않는다.
 */
export const BUTTONS = { RED: 0, YELLOW: 1, GREEN: 2, BLUE: 3 };
const KEY_MAP = { '1': 0, '2': 1, '3': 2, '4': 3 };
const WS_URL = 'ws://localhost:8765';

export class Input {
  constructor() {
    this.pressed = new Set();      // 지금 눌려 있는 버튼
    this._down = new Set();        // 눌림 콜백들
    this._up = new Set();          // 뗌 콜백들
    this._fromBridge = new Set();  // 브리지가 눌렀다고 알려 온 것만 추적
  }

  /** 버튼 눌림 구독. onDown((id) => {...}) */
  onDown(fn) { this._down.add(fn); return () => this._down.delete(fn); }
  /** 버튼 뗌 구독 */
  onUp(fn) { this._up.add(fn); return () => this._up.delete(fn); }

  emit(type, id) {
    if (type === 'down') {
      if (this.pressed.has(id)) return;        // 같은 버튼 중복 눌림 무시
      this.pressed.add(id);
      for (const fn of [...this._down]) fn(id);
    } else {
      this.pressed.delete(id);
      for (const fn of [...this._up]) fn(id);
    }
  }

  /** 버튼 하나를 기다린다. await input.wait() → 누른 id */
  wait() {
    return new Promise((resolve) => {
      const off = this.onDown((id) => { off(); resolve(id); });
    });
  }

  start() {
    // --- 키보드 (개발용, 실물에서도 살아 있다) ---
    addEventListener('keydown', (ev) => {
      if (ev.repeat) return;                   // 키 반복 이벤트 무시
      const id = KEY_MAP[ev.key];
      if (id === undefined) return;
      ev.preventDefault();
      this.emit('down', id);
    });
    addEventListener('keyup', (ev) => {
      const id = KEY_MAP[ev.key];
      if (id === undefined) return;
      this.emit('up', id);
    });
    // 창 포커스를 잃으면 keyup 을 못 받는다 → 눌림 상태 정리
    addEventListener('blur', () => {
      for (const id of [...this.pressed]) this.emit('up', id);
    });

    this._connect();
    return this;
  }

  /** 아케이드 버튼 브리지. 없으면 조용히 키보드 모드로만 동작한다. */
  _connect() {
    let ws;
    try { ws = new WebSocket(WS_URL); } catch { return this._retry(); }

    ws.addEventListener('message', (ev) => {
      let msg;
      try { msg = JSON.parse(ev.data); } catch { return; }
      if (msg?.type !== 'button') return;      // hello 등은 무시
      const id = Number(msg.id);
      if (msg.state === 'down') this._fromBridge.add(id);
      else this._fromBridge.delete(id);
      this.emit(msg.state, id);
    });

    ws.addEventListener('close', () => {
      // 브리지가 알려 온 버튼만 되돌린다. 키보드로 누르고 있는 것은 건드리지 않는다.
      for (const id of [...this._fromBridge]) this.emit('up', id);
      this._fromBridge.clear();
      this._retry();
    });
    ws.addEventListener('error', () => {});    // close 로 이어지므로 무시
  }

  _retry() {
    // 브리지 없는 PC 에서는 영영 안 붙으므로 간격을 늘려 콘솔을 어지럽히지 않는다
    this._delay = Math.min((this._delay ?? 3000) * 2, 60000);
    setTimeout(() => this._connect(), this._delay);
  }
}
```

사용 예:

```js
import { Input, BUTTONS } from './js/input.js';

const input = new Input().start();

input.onDown((id) => {
  console.log('눌림:', id);
  if (id === BUTTONS.RED) { /* 빨강 눌렀을 때 */ }
});

// 또는 한 번 기다리기
const picked = await input.wait();
```

## 7. 웹앱 필수 규칙

### 반드시 지킬 것

| 규칙 | 이유 |
|---|---|
| **빌드 도구·npm·번들러 없음** | 저장소를 그대로 정적 서빙해야 한다 |
| **CDN 링크 없음** | 게임기가 오프라인일 수 있다. 폰트·라이브러리는 저장소에 동봉 |
| **순수 HTML + CSS + ES 모듈 JS** | `<script type="module">` |
| **`index.html` 은 저장소 루트에** | GitHub Pages 가 그래야 게임을 띄운다 (§9) |
| **키보드 `1 2 3 4` 로 전부 플레이 가능** | 개발·점검이 PC에서 되어야 한다 |
| **입력은 버튼 4개만** | 마우스·터치·문자입력에 의존하면 실물에서 못 쓴다 |

### 로컬에서 띄우는 법

```bash
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000
```

> **`file://` 로 HTML 을 직접 열면 ES 모듈이 막혀 동작하지 않는다.** 반드시 위 명령으로.

### 키오스크 화면 기본 CSS

```css
html, body {
  margin: 0; padding: 0; height: 100%;
  overflow: hidden;        /* 스크롤바가 보이면 안 된다 */
}
body {
  cursor: none;            /* 마우스 커서 숨김 */
  user-select: none;
  -webkit-user-select: none;
  overscroll-behavior: none;
}
```

### 반응형 — 화면 크기를 모른다고 가정한다

포터블 모니터 해상도가 개발 PC와 다르다. **px 고정 크기를 쓰지 말고**
`vh`·`vw`·`clamp()` 를 쓴다.

```css
/* 나쁨 */  .title { font-size: 48px; }
/* 좋음 */  .title { font-size: clamp(24px, 6vh, 72px); }
```

### 소리

**Web Audio 합성**을 쓴다 (음원 파일 불필요, 오프라인 안전).

```js
const ac = new AudioContext();
function beep(freq = 440, dur = 0.15) {
  const osc = ac.createOscillator();
  const env = ac.createGain();
  osc.frequency.value = freq;
  env.gain.setValueAtTime(0.0001, ac.currentTime);
  env.gain.exponentialRampToValueAtTime(0.3, ac.currentTime + 0.01);
  env.gain.exponentialRampToValueAtTime(0.0001, ac.currentTime + dur);
  osc.connect(env).connect(ac.destination);
  osc.start(); osc.stop(ac.currentTime + dur + 0.02);
}
```

> **브라우저 정책상 첫 사용자 입력 전까지 소리가 잠겨 있다.**
> 타이틀에서 첫 버튼을 누를 때 `ac.resume()` 을 호출한다. 그 전에 무음인 것은 정상이다.

## 8. 게임 기획 제약 — 4개 버튼으로 되는 것

### 쓸 수 있는 조작

| 조작 | 구현 |
|---|---|
| 버튼 하나 누르기 | `onDown(id)` |
| 4지선다 | 화면에 빨/노/초/파 칸 4개 → 그 색 버튼 |
| 순서대로 누르기 | 눌림 순서를 배열에 쌓기 |
| 길게 누르기 | `onDown` ~ `onUp` 시간 재기 |
| 두 개 동시 | `input.pressed` 크기 확인 |
| 연타 | 일정 시간 안의 `onDown` 횟수 |
| 좌우 이동 | 빨강=왼쪽, 파랑=오른쪽 (양 끝 버튼) |
| 타이밍 맞추기 | 화면 표시와 누른 시각 차이 |

### 쓸 수 없는 것

- 문자·숫자 입력 (이름 입력 화면 금지)
- 마우스 클릭·드래그·터치 스와이프
- 5개 이상의 동시 선택지

### 게임 아이디어 (수학문화관 맥락)

| 게임 | 4버튼 사용 |
|---|---|
| 기억력 게임 | 나온 색·숫자·모양 순서를 그대로 재현 |
| 사칙연산 퀴즈 | 4지선다로 정답 고르기 |
| 도형 이름 맞히기 | 도형 하나 → 이름 4개 중 선택 |
| 소수/짝수 판별 | 조건에 맞는 것만 빠르게 누르기 |
| 반응속도 대결 | 화면이 바뀌는 순간 제일 먼저 누르기 |
| 리듬 게임 | 색이 떨어지면 그 색 버튼을 타이밍에 |
| 규칙 찾기(패턴) | 다음에 올 것을 4지선다로 |
| 무게 비교·부등호 | 왼쪽/오른쪽/같다 를 버튼에 배정 |
| 좌표 찾기 | 빨=왼, 파=오, 노=위, 초=아래 로 커서 이동 |
| 확률 실험 | 예측을 버튼으로 고르고 결과 누적 통계 보기 |

### 부스 운영 조건 (전시물이라는 것을 잊지 말 것)

- **매번 다른 사람이 온다.** 설명 없이 30초 안에 이해되어야 한다.
- **끝이 있어야 한다.** 무한 게임은 다음 사람이 못 온다. 1~3분 안에 끝나게.
- **"최고 기록" 표시는 의미가 약하다.** 주인이 매번 바뀌고, 끝이 있는 게임은
  며칠이면 만점에 닿아 안 바뀌는 죽은 숫자가 된다. 대신 **완주 횟수** 같은
  누적 숫자가 낫다.
- **초기화가 자동이어야 한다.** 방치하면 알아서 타이틀로 돌아가게 한다.
- **탈출 경로를 만든다.** 예: 빨강+파랑 2초 동시 누르기 → 타이틀.
  (양 끝 버튼이라 실수로 눌리지 않는다)

## 10. 실물 게임기에 올리기

우노 Q 리눅스의 **보드 화면 앞 터미널**에서 진행한다.
(SSH 로만 붙으면 자동시작 등록이 실패할 수 있다)

```bash
# 1) 게임 받기
git clone <내 저장소 주소> ~/mygame
cd ~/mygame

# 2) 브리지 의존성 (이 보드에는 pip3 가 없다. apt 로 설치)
sudo apt install -y python3-websockets python3-serial
```

### 3) 브리지를 App Lab 앱으로 등록

1. App Lab 에서 기존 앱을 **Duplicate** → **Rename**
   (빈 앱을 만드는 것보다 확실하다. 보드 설정이 그대로 복제된다)
2. 만들어진 폴더 확인:
   ```bash
   ls -lt ~/ArduinoApps/ | head -3
   ```
3. 그 폴더의 `sketch/sketch.ino`, `python/main.py`, `app.yaml` 을
   브리지 것으로 덮어쓴다
4. App Lab 에서 그 앱 **Run** → 스케치가 구워지고 브리지가 뜬다
5. 하단 **Python 탭**에서 로그 확인 → 버튼을 눌러 `0 → 1 → 2 → 3` 순서 확인
6. 앱 카드 `⋯` → **`Run at startup` 켜기**

### 4) 웹서버 + 키오스크 자동시작

`python3 -m http.server` 로 게임을 띄우고, 크로미움을 전체화면으로 자동 실행한다.
`~/.config/autostart/` 에 `.desktop` 파일을 두는 방식이 이 보드에서 확실히 동작한다.

크로미움 실행 플래그:

```
--kiosk
--noerrdialogs --disable-infobars --disable-session-crashed-bubble
--disable-features=Translate,TranslateUI
--autoplay-policy=no-user-gesture-required
--check-for-update-interval=31536000
--user-data-dir=$HOME/.mygame-kiosk-profile
--no-first-run --no-default-browser-check --restore-last-session=false
http://localhost:8000/
```

### 5) 장시간 구동 설정

```bash
xset s off -dpms                     # 화면 절전·블랭킹 끄기 (X11)
loginctl enable-linger $USER         # 로그인 없이도 부팅 시 실행
```

### 6) 소리 (PipeWire — `pactl` 이 아니라 `wpctl`)

```bash
wpctl status                                      # Sinks 에서 * 확인
wpctl set-default <번호>                           # 스피커 쪽으로
wpctl set-volume @DEFAULT_AUDIO_SINK@ 0.85
alsamixer                                         # F6 → 카드 선택 → MM 이면 M 키로 음소거 해제
sudo alsactl store                                # 재부팅 후에도 유지
speaker-test -t wav -c 2                          # 확인 (Ctrl+C)
```

## 11. 실제로 겪은 함정 목록

이 프로젝트에서 **직접 부딪혀 해결한 것들**이다. 미리 알면 시간을 아낀다.

### 하드웨어

| 함정 | 해결 |
|---|---|
| 버튼이 계속 눌린 상태로 인식 | **NC ②** 단자에 물렸다 → `NO ③` 으로 |
| 아무 버튼도 안 먹음 | GND 데이지체인이 빠졌다 (단일 고장점) |
| 특정 버튼만 안 됨 | 그 버튼의 D핀 접점 |
| 순서가 뒤바뀜 | D2~D5 를 왼쪽부터 순서대로 다시 |
| 화면이 안 나옴 | 허브가 **DP Alt-Mode** 를 지원하는지 (충전 전용 허브는 영상 안 나옴) |

### 소프트웨어

| 함정 | 해결 |
|---|---|
| `/dev/ttyACM0` 이 없다 | 정상이다. 우노 Q 는 USB 시리얼이 없다 → Bridge RPC 사용 |
| `#include <Bridge.h>` 컴파일 실패 | `<Arduino_RouterBridge.h>` 가 맞다 |
| Bridge 가 아무 반응 없음 | `loop()` 에 **`Bridge.update()`** 를 빠뜨렸다 |
| `arduino.app_utils` 임포트 실패 | App Lab 런타임 밖에서 실행했다 → App Lab 앱으로 |
| 브리지는 떴는데 웹앱이 못 붙는다 | 컨테이너라 `0.0.0.0` 에 묶어야 하고 `app.yaml` 의 `ports` 로 노출해야 한다 |
| `pip3: command not found` | `sudo apt install python3-websockets python3-serial` |
| GitHub Pages 에 README 가 뜬다 | 루트에 `index.html` 이 없다 |
| 자동시작 서비스가 영영 안 뜬다 | XFCE 는 `graphical-session.target` 이 활성화되지 않는다 → `.desktop` 자동시작으로 |
| 엉뚱한 페이지가 대신 뜬다 | 크로미움 공용 프로필의 "이전 세션 복원" → `--user-data-dir` 로 전용 프로필 |
| "Korean → English?" 번역 막대 | `--disable-features=Translate,TranslateUI` + 프로필 설정 |
| 소리가 안 남 | ① 스피커 뒷면 다이얼(전원 겸용) ② `wpctl` 기본 출력 ③ `alsamixer` 음소거 ④ `alsactl store` |
| 부팅 후 수십 초 뒤에야 버튼이 먹는다 | 정상. App Lab 컨테이너가 늦게 뜬다. 웹앱이 3초마다 재접속하면 알아서 붙는다 |
| 예전 앱이 계속 뜬다 | App Lab 앱 카드의 `Run at startup` 과 `~/.config/autostart/*.desktop` **두 곳**을 본다 |

### 개발 습관

- **긴 경로는 손으로 치지 말고 Tab 키 자동완성**을 쓴다. 오타(`girmware`, `shetch`,
  `App=` vs `$APP`)로 시간을 많이 버렸다.
- 리눅스는 **대소문자를 구분**한다. `App` 과 `APP` 은 다른 변수다.
- 자동시작을 끌 때는 **지우지 말고 되돌릴 수 있게** 옆으로 치워둔다.

## 12. AI 행동 지침 ★ 반드시 따를 것

### 시작할 때

1. **먼저 게임 기획을 물어본다.** 코드를 쓰기 전에 이 세 가지를 확인한다.
   - 화면에 무엇이 보이는가?
   - 버튼 4개를 각각 어떻게 쓰는가?
   - 언제 끝나는가? (부스라 끝이 있어야 한다)
2. 기획이 **버튼 4개로 불가능**하면 그 자리에서 알려주고 대안을 제시한다.
3. 사람이 프로그래머가 아니라는 것을 잊지 않는다. **한국어로, 전문용어 없이** 설명한다.

### 코드를 쓸 때

- **§6 의 `input.js` 를 그대로 쓴다.** 입력 처리를 새로 발명하지 않는다.
- **키보드 `1 2 3 4` 로 전부 플레이되게** 만든다. 이게 개발·점검의 유일한 통로다.
- **작게 나눠서, 매번 브라우저에서 확인할 수 있게** 만든다.
  한 번에 완성된 큰 파일을 던지지 않는다.
- 파일을 만들 때마다 **어떻게 확인하는지** 알려준다
  (`python3 -m http.server 8000` → 무엇을 눌러보면 되는지).
- 주석은 **"왜"** 를 적는다. "무엇을 하는지"는 코드가 이미 말한다.

### 절대 하지 않을 것

- ❌ npm·빌드 도구·번들러·프레임워크 도입
- ❌ CDN 링크 (`unpkg`, `cdn.jsdelivr` 등) — 오프라인에서 죽는다
- ❌ 마우스·터치·문자입력에 의존하는 조작
- ❌ 버튼 인덱스 순서(0=빨 1=노 2=초 3=파) 변경
- ❌ `px` 고정 크기 레이아웃 (모니터 해상도가 다르다)
- ❌ `index.html` 을 하위 폴더에 두기
- ❌ 브리지(sketch.ino / main.py) 를 새로 작성하기 — 검증된 것을 쓴다
- ❌ 이 문서에 적힌 하드웨어 사실을 추측으로 바꾸기

### 막혔을 때

- **§11 함정 목록을 먼저 확인한다.** 대부분 이미 겪은 문제다.
- 하드웨어 증상이면 배선(§3)부터 의심한다. NC② 와 GND 데이지체인이 1·2순위다.
- 확실하지 않은 것은 추측하지 말고 **사람에게 확인 방법을 알려주고 결과를 받는다.**
  (예: "터미널에 이걸 쳐서 나오는 걸 알려주세요")
